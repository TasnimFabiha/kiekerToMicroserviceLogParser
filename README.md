# Kieker To Microservice Log Parser

This project converts Kieker operation dependency graphs (DOT files, one per feature/capability) and method size CSVs into the dynamic input of [toMicroservice](https://github.com/TasnimFabiha/toMicroservice): the execution log (`<project>.log`) and the feature list (`generalFunctionalities.list`).

## Features

- **Reads Kieker DOT graph files** to extract method call dependencies.
- **Parses method size CSV files** (generated by [java-param-size-estimator](https://github.com/TasnimFabiha/java-param-size-estimator)) for the parameter size of each call.
- **Writes every call of the graph** in the log format of toMicroservice (see **Output Format**).
- **Maps features to methods** and outputs them in a structured format.
- **Removes previous outputs** of a project before writing new ones.

## Project Structure

```
.
├── DotGraphAnalyzer.py          # reads a DOT graph: methods, calls, depth, parameter size
├── MethodSizeReader.py          # reads method_parameters_sizeOf.csv
├── MethodWriter.py              # writes the log and the feature list
├── ProjectProcessor.py          # processes all DOT graphs of a project
├── LogConverterFromGraph.py     # entry point: list of projects
└── data/
    ├── <project_name>/
    │   ├── assemblyOperationDependencyGraph_<feature>.dot   # one per feature/capability
    │   └── method_parameters_sizeOf.csv                    # output of java-param-size-estimator
    ├── <project_name>_output_methods.txt                   # log (toMicroservice: <project>.log)
    └── <project_name>_output_general_functionality.txt     # feature list (toMicroservice: generalFunctionalities.list)
```

The DOT graphs contain only application methods (declared in the system's Java source) and the `Entry` node. Generated code (e.g. Fenix `*_Base` classes, `@Atomic` wrappers, lambdas) and Kieker's own classes are removed from Kieker's graphs beforehand; a call through removed nodes, A -> (removed) -> B, is kept as the edge A -> B.

## Usage

1. **Prepare your data:**
   - Place your Kieker DOT files, named `assemblyOperationDependencyGraph_<feature>.dot`, and the `method_parameters_sizeOf.csv` (generated by [java-param-size-estimator](https://github.com/TasnimFabiha/java-param-size-estimator)) in `data/<project_name>/`.

2. **Configure your project:**
   - Edit `projects` and `base_path` in `LogConverterFromGraph.py`.

3. **Run the parser:**
   ```bash
   python LogConverterFromGraph.py
   ```

4. **Check the outputs** (in `data/`):
   - `<project_name>_output_methods.txt`
   - `<project_name>_output_general_functionality.txt`

## Output Format

- **Methods Output (log):**
  For each feature, a line with the feature's methods, followed by every call `caller -> callee` of the feature's graph as three lines:
  ```
  SF:feature1<pkg.ClassA.methodA,pkg.ClassB.methodB,...>
  SF:
  Class:pkg.ClassA#Method:methodA#SizeOf:16#Deep:1#Thread:main
  Class:pkg.ClassB#Method:methodB#SizeOf:24#Deep:2#Thread:main
  SF:
  ...
  ```
  toMicroservice adds an edge from each log line to the next one, and starts again from its start vertex after an `SF:` line, so each pair of method lines is exactly one call of the graph.
  - `SizeOf`: the total parameter size of the called method, from `method_parameters_sizeOf.csv` (0 if the method is not in the file). Constructors (`<init>` in the graph, written as `init`) are looked up by their class name, as in the CSV. Overloaded methods share one size, since the graph does not contain parameter types.
  - `Deep`: the distance of the method from `Entry` in the graph.

- **General Functionality Output:**
  ```
  SF:feature1<methodA,methodB>#feature2<methodC,methodD>
  ```

- Python 3.6+
- No external dependencies (uses only the Python standard library)
